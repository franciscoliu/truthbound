AUTONOMY NEEDS PROOF

Test policy-governed agents before release.

Truthbound compiles a written policy into a reviewable check, generates a test case for each outcome the check distinguishes, and checks the agent's consequential tool calls against the approved rules while it works.

In our demo, a low-cost support agent issued a cancellation-and-refund call on a $4,986 simulated reservation that the policy says is not eligible. The same check blocked the call.

WHY IT MATTERS

More autonomy.
More at stake.

An agent's decision can trigger a refund, a release or a promise to a customer. A written policy only protects you if the agent follows it, case after case, and you can show which rule applied and why.

What Truthbound does, before
and after an agent release.

  1. 01Compile the policy for reviewPolicy text becomes an executable check over a finite set of conditions, validated for syntax, totality and rule conflicts. A policy owner still reviews it for fidelity to the document.
  2. 02Test each outcome it distinguishesEnumerate the combinations the compiled check can tell apart, generate one realistic case per outcome, grade the agent against the check.
  3. 03Check actions at runtimeIn the demo integration, refund and transfer calls and the final answer are checked against the compiled rules before they take effect.

SEE IT ON A REAL POLICY

A $4,986 refund call,
caught twice.

We compiled an airline cancellation policy, generated a case for each of the seven outcomes the compiled check distinguishes, and ran a low-cost support agent with real tools against a simulated airline backend. It issued a refund call the policy forbids. Testing each outcome found it; the runtime check blocked it. With the check on, the same cheap model finished 7/7 on those seven cases. GPT-5.5 and Claude Opus 5.5 each scored 7/7 unguarded in one run, at roughly fifty times the inference price.
